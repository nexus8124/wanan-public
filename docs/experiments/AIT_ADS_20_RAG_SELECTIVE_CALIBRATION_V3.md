# AIT-ADS-20 选择性 RAG 校准实验 v3

## 实验目的

验证扩展知识库和收紧后的 RAG 门控是否能在不扩大退化风险的前提下：

- 修正无知识初判中的待查/误判；
- 避免对全部高置信样本执行无价值的二次模型调用；
- 保持 `KB-*` 引用可追溯；
- 降低上一版宽泛行为域强制校准的 Token 和延迟开销。

## 实验配置

| 项目 | 值 |
|---|---|
| 时间 | 2026-07-27 |
| 数据集 | `data/processed/ait_ads_eval.json` |
| 样本数 | 20（标签均衡确定性子集） |
| 标签依据 | `time_window_weak` |
| Provider | DeepSeek 官方 API |
| 模型 | `deepseek-v4-flash` |
| 温度 | 0.1 |
| Agent 策略 | `judge_only` |
| RAG 策略 | `selective_weak_signal_calibration_v3` |
| RAG 语料版本 | `rag-v2-20260727` |
| 知识条目 | 39（ATT&CK 20 + Playbook 19） |
| ReAct | 关闭，隔离第三阶段变量 |

本轮 No-RAG 基线不是单独再次请求模型，而是使用每条样本在 RAG 介入前已经
生成的 `initial_pred`。因此“初判→RAG 后”是同一次运行、同一条初判上的配对
比较，可避免两轮独立请求带来的模型随机波动。

## 修正案例

### Dovecot 成功认证

- 初判：待查
- RAG 后：假阳
- 引用：`KB-PLAYBOOK-PB-MAIL-AUTH-001`
- 依据：内网可信来源、TLS 正常、没有失败认证和后续异常行为，符合正常邮件
  客户端同步模式。

### Web 多路径枚举

- 初判：待查
- RAG 后：真阳
- 引用：
  - `KB-PLAYBOOK-PB-WEB-ACCESS-001`
  - `KB-PLAYBOOK-PB-NETWORK-SCAN-001`
- 依据：同一来源在短时间形成大规模、多路径枚举模式，已有事件事实支持扫描，
  Playbook 用于区分普通单次 404 与系统性侦察。

## 未修正案例

### `.biz` DNS 查询

初判为真阳，RAG 根据 `KB-PLAYBOOK-PB-DNS-ANOMALY-001` 认为现有事实只能
支持待查。系统按护栏拒绝把已决结论降级为待查，因此仍与弱时间窗标签“假阳”
不一致。这说明知识校准已介入，但知识不能代替进程、域名信誉和业务归属证据。

### TLS 无效握手

初判待查，模型未生成有效 `KB-*` 引用，后融合未采纳。仅凭无效 TLS 握手仍
不足以区分兼容性问题、健康检查、扫描或攻击。

## 结论

本轮满足第三阶段的核心工程和同轮实验要求：

- 正确知识可以被稳定召回；
- RAG 带来 2 次修正、0 次退化；
- 同轮准确率提升 10 个百分点；
- 强制触发从上一版的全样本触发收紧至 20%；
- 没有检索或后融合错误；
- 未通过放宽安全护栏来迎合弱标签。

由于 AIT-ADS 使用攻击时间窗弱标签，单轮 20 条结果不能证明总体泛化能力。
后续应在冻结样本上重复运行，并在 CAM-LDS 等具备事件级证据的数据集上复核。
